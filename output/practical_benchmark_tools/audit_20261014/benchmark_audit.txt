READ-ONLY BENCHMARK AUDIT — 14 OCTOBER 2026

Conclusion
The practical Claude pilot does not establish that shortening the prompt improved one-shot quality. It generated only the short-input condition, while the longer prompts were token-counted for context. Historical scores also changed generator, evaluator aggregation, response format, numerical verification, delivery behavior, and confirmation information. The current FlowPilot deficit is principally a delivery regression in the no-clarification input path; automated judges additionally missed genuine one-shot arithmetic defects and copied a false FlowPilot identity warning into a chemical penalty.

Recommended experiment
Freeze the repaired source and a new evaluator protocol before generation. Use Claude Sonnet 4.6 in three arms over the same three practical cases, one generation per arm and case. Arms are practical one-shot prose; guidance-enriched one-shot prose; and practical FlowPilot. Preserve batch facts, full inventory, short objective, no human confirmation, one-shot system message, prose response policy, output allowance and sampling settings. The only change between the two one-shot arms is the attached generic checklist, not hidden facts or a reaction-identity answer. The proposed checklist is in guidance_enrichment.txt. Use fresh outcomes, all retained, with no score-based retries. This nine-outcome pilot distinguishes whether guidance helps this generator from whether repaired FlowPilot improves delivery. It is developmental evidence, with no variance or superiority claim from n=1.

Evaluator improvements applied identically
Keep the 14 criteria, weights and score anchors. Use strict JSON from the start. Make the added instructions explicit in evaluator versioning: check all reported numerical relations with operands and units; distinguish independently recalculated values from candidate assertions; verify validator warnings against raw protocol rather than treating them as chemistry facts; do not penalize SCREEN, low confidence or acknowledged unmeasured quantities by themselves; quote a concrete defect for every below-4 rating. Any delivery block can reduce executability without automatically establishing the validator's claimed chemistry error. Full prose or structured output must receive the same scientific standard.

Prefer a separate format-neutral numeric extraction/verification worksheet for both architectures. Each extracted claim must contain an exact quotation and source path, value, unit and reference basis; ambiguous or conflicting values remain ambiguous or conflicting, never silently repaired. Deterministic checks should calculate concentration x flow, summed flow, V/Q with explicit time basis, gas ideal-law conversion and gas equivalents using declared temperature/absolute pressure/composition. Never interpret sccm as different from standard mL/min at the same reference state. Distinguish unavailable packed-bed holdup from a wrong arithmetic claim. Record machine checks as evidence, not as manually selected deductions from a total score. A lightweight LLM extraction is not automatically ground truth and requires quote validation; a generic parser should not privilege structured FlowPilot fields while ignoring prose.

If judging instructions or worksheets change, re-evaluate the old six immutable outputs under the same new evaluator protocol to estimate an old-versus-repaired score change. Otherwise compare old and new delivery and objectively verified arithmetic separately, because score shifts also reflect judge protocol. No old rating should be overwritten or reported as corrected original data. The old normalized packets contain the complete prose and delivery state needed for these audits; adding missing evidence is not the primary issue.
